# Singularity Dynasty

A subscription website for a dynasty fantasy football data-science business. Originally a single static `index.html` landing page (kept at repo root for reference); the live build is now a Next.js app in `web/`. This file is context for continuing the build in Claude Code.

## Brand
- **Name:** Singularity Dynasty
- **Theme:** space / black-hole aesthetic, with a secondary neon blue accent alongside the primary orange "event horizon" glow. A few minimalist football touches are woven in (the draft board grid mockup) but the site is not fully space-themed or fully football-themed — it's a deliberate blend.
- **Tagline / core concept:** "Where the data reaches its endpoint." The brand metaphor is gravity: scattered stats, trends, and matchups all collapse toward one clear number. The top pricing tier is literally named "Singularity" — the endpoint the whole brand points toward.
- **Voice:** confident, data-first, anti-"gut feel". Founder is a data analyst who got tired of vibes-based rankings.

## Design system
- Colors: `--void` (#07070C, near-black bg), `--void-panel`/`--void-panel-2` (card backgrounds), `--horizon`/`--horizon-gold` (orange/gold accretion-disk accent, primary), `--neon-blue`/`--neon-blue-dim` (secondary accent, deliberately present throughout — ticker, nav, node numerals, footer, not just decorative glows), `--star`/`--star-dim` (text)
- **Light mode exists** alongside the dark theme above (dark is still the default). Activated via `@media (prefers-color-scheme: light)` plus an explicit `:root[data-theme="light"]` override, toggled by the sun/moon button (`app/ThemeToggle.js`) on every page, persisted to `localStorage`. Theme-aware values that aren't plain hex (shadows, the starfield dot color, the ticker/menu-btn scrim, orbit-ring lines) are done as `--x-rgb` custom properties consumed via `rgba(var(--x-rgb), alpha)` — **never bake a theme-specific color into a static SVG data-URI**; that's what broke the feature-list bullet icons in light mode the first time (see globals.css `.feature-list li::before`, now a `radial-gradient` using `var(--void-panel)` instead).
- Fonts: Space Grotesk (headings), Inter (body), IBM Plex Mono (data/stats/mono) — loaded via `next/font/google` in `web/app/layout.js`, referenced in CSS as `var(--font-space-grotesk)` etc.
- **Golden Gate material (macOS 27's refined Liquid Glass, applied to the void theme):** one block at the end of `web/app/globals.css`, driven by tokens (`--glass-alpha`, `--glass-data-alpha`, `--glass-blur`, `--glass-spec`, `--glass-rim`, `--glass-edge`, and the container radius scale `--r-sm/md/lg` = 8/12/16). Top-level surfaces (panels, pricing cards, auth/legal cards, the header + ticker as one uniform toolbar, floating round buttons) blur what is behind them with a brighter top highlight and a darkened inner edge; cards nested inside them (stat panels, comps, feed cards) get the translucent fill + rim light but no blur of their own; segmented controls are a recessed track with a lit thumb; `.btn-primary` has a lit top edge, `.btn-ghost` is a glass pill. Data tables use a higher alpha so they stay legible and go fully solid on phones. Transparency is fixed at `--glass-alpha` (a clear-to-tinted slider button existed briefly and was removed on request -- don't re-add it). `prefers-reduced-transparency` makes the panels near-solid. A faint gold + blue glow sits fixed behind the tool pages so the glass has something to catch. The palette and the three fonts are unchanged. New surfaces should join the existing selector lists in that block rather than adding their own backgrounds.
- **Hover tips:** `web/app/Tooltip.js` (mounted once in `layout.js`) replaces the browser's plain native tooltip everywhere, in the glass material with the gold-to-blue hairline. It works off the existing `title` attribute -- put hover text in `title` like before and it picks it up; while a tip shows, the attribute is lifted off the element (so the native box can't appear) and restored when it hides. Mouse and keyboard focus only; touch has no hover.
- Signature motifs: starfield background (mouse-parallaxed), dual radial glows (orange + blue), a draggable orbit ring of "signal chips" in the hero, an orbital hub-and-node selector currently showing 5 of the 6 tools (Best Ball Rankings is sunset — see "Product features" — its node/panel were removed and the arc's `--nx`/`--ny` offsets recomputed for 5 nodes, not 6), a gravity-well playground (canvas particle sim) as the last section before the footer, click-burst micro-interactions on buttons
- No page-break dividers between sections (an earlier "orbit divider" motif was removed by request — don't reintroduce it unless asked)
- **Every page shares one header/ticker setup**, `app/SiteHeader.js` — a full-width fixed `.site-header` bar (plain in-flow `.brandmark` on the left, not a floating pill), nav links spread across a wide center band with an invisible equal-width spacer balancing the brand on the other side, Get Started/Sign In bookending the section links, theme toggle fixed independently at top-right, plus the fixed telemetry ticker above it. Below 1180px width it collapses to the hamburger + `.radial-menu` fallback instead (a full link row doesn't fit at that width). `SiteHeader` fetches its own auth state and real ticker data (latest `redraft_rankings` trend rows) and mounts `InteractiveScript` once, so no page needs its own copy of any of this — it fully replaced the old per-page-type brand marks (tool pages' fixed floating pill, auth/legal pages' static `.auth-back` link, and Player Season Simulations' one-off static/neon-blue pill variant). Nav/radial-menu links point at `/#section` (not bare `#section`) so they work as a real navigation back to the homepage from any other page — `InteractiveScript` only intercepts + smooth-scrolls when already on that path. **Gotcha:** `html{scroll-behavior:smooth}` silently breaks the browser's native scroll-to-fragment-on-load (`scrollIntoView({behavior:'auto'})` inherits that CSS setting instead of jumping instantly); `InteractiveScript` works around it with an explicit `behavior:'instant'` scroll-to-hash on mount — don't "simplify" that away.

## Pricing tiers
Tiers are framed as **titles the subscriber earns**, not plan names:
- **Stargazer** — Free
- **Explorer** — $9/mo (~$7/mo annual), floating "MOST POPULAR" ribbon badge (the in-card eyebrow label itself reads "Standard Access" to avoid duplicating the popularity claim in two different words)
- **Singularity** — $24/mo (~$19/mo annual), marked "Full Access"

Pricing section includes a "14-DAY REFUND · CANCEL ANYTIME" reassurance line beneath the cards. The Pricing section comes right after Tools, before the Feed/newsletter section (order was deliberately swapped from an earlier build where Feed came first).

Naming history (don't reuse): Navigator, Pathfinder, Voyager, Orbiter, Ascendant, Drifter, Rover, Sojourner, Nomad, Wanderer were all considered and rejected before landing on Explorer.

    - `app/tools/player-simulations/` — `0006_player_simulations.sql` (floor/median/ceiling per player). Renders a CSS range-bar per row, not just numbers. **Singularity-only** — Explorer does NOT get full access here, unlike the three above; this matches the pricing copy exactly and is worth double-checking whenever this page is touched.
      Floor/median/ceiling method (season sims, `model/projection_engine.R`, on by default; `BANK_SEASON_TOTALS=0` reverts): once games have been played, a player's real totals so far are locked in and only his team's remaining games are simulated. The median is that simulation's median (injury history included, unchanged ranking basis). Floor and ceiling are distances from that median with the shape of a healthy player's range (runs where he plays 75%+ of the remaining games), stretched by per-position/stat/week factors in the generated `model/banked_k_table.R` so ~10% of players who stay on the field land at or below the floor / at or above the ceiling (out-of-sample). A player who actually misses games is lowered by the next weekly run because those games are banked; the floor deliberately does not price in a lost season. The table is a ONE-TIME calibration (`backtest_banked_calibration.R` then `analyze_banked_calibration.R`); do not rerun it weekly. Earlier weeks on the week scrubber stay as published.
      Player archetypes (RB/WR/TE/QB role groups; QB uses a 3-season window and rushing yards a game so Lamar/Hurts/Allen land together): `model/player_archetypes.R` clusters role-only features (workload and production MIX, never volume) with PCA + k-means. `fit` is a ONE-TIME step that writes the frozen `model/archetype_model.R` (scaling, PCA axes, centres, names -- commit it); the weekly run only assigns players to those frozen groups (`Rscript player_archetypes.R`) and `scripts/publish-player-archetypes.mjs` upserts `player_archetypes` (migration `0034`, run once in the Supabase SQL editor). The weekly assignment weights recent games (`ARCH_HALF_LIFE` = 4 games, backtested on 2025: ~67-74% of real role changes show up within 4 games vs 12-36% with equal weights), so a player's label can change week to week; `confidence`/`runner_up` mark boundary players. The weekly hook in `scripts/weekly-run.mjs` is never fatal. Shown on Player Season Simulations only: a "Player role" block (pill, the group's description from `web/lib/archetypes.js` as its caption, plus a "Close to <runner-up>" note when confidence < 0.15) above the stat table, and a short-named pill in the empty first column of each comparison card's Floor/Median/Ceiling picker row (`ArchetypePill`). Loaded optionally in `player-simulations/page.js` (`loadArchetypes`) -- a missing table or QB just shows nothing.
      Other groupings (`model/player_groups.R` -> `scripts/publish-player-groups.mjs` -> table `player_groups`, migration `0035`, generic `kind` column so new groupings need no new table; same never-fatal weekly hook): `sustainability` (Running Hot / In Line / Running Cold = actual vs expected fantasy points per game, position-adjusted; backtested -- hot players fell ~3.2 pts/game next window, cold rose ~1.7-2.2; the gap itself is not repeatable, so it is a regression signal, not a skill label) and `career_stage` (Ascending / Prime / Decline Watch / Late Career, QB: Ascending / Prime / Veteran; cutoffs from the README's longitudinal age curves).     - **Weekly Rec TD for WR/TE** (the Rec TD column and custom-scoring component, not the headline median): `model/rec_td_blend.R` -- 75% expected receiving TDs (ffopportunity, half-life 8 games) + 25% slow-decay actual TDs, last 30 games, instead of the old fast-decay (0.69/0.60) mean of actual TDs. - When verifying a change against fresh Supabase data (new rows, not just new code) via the local dev server, a plain `rm -rf web/.next/cache` + restart is sometimes NOT enough for the new data to show up — this Next.js fork appears to cache `unstable_cache` results somewhere under `web/.next` beyond just the `cache/` subfolder. If a server-computed value still reflects pre-update data after a cache-only clear and restart, wipe the whole `web/.next` directory (not just `web/.next/cache`) and restart before concluding there's a real code bug. **Order matters**: stop the dev server first, *then* `rm -rf web/.next`, *then* start a fresh server. Deleting `.next` while a server process still has it open corrupts its on-disk state (`ENOENT`/`build-manifest.json`/SST-file errors, ends in a 500) and needs a clean stop → wipe → start cycle to recover, not another cache clear on top.
