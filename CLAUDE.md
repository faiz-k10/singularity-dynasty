# Singularity Dynasty

A subscription website for a dynasty fantasy football data-science business. Originally a single static `index.html` landing page (kept at repo root for reference); the live build is now a Next.js app in `web/`. This file is context for continuing the build in Claude Code.

## Brand
- **Name:** Singularity Dynasty
- **Theme:** space / black-hole aesthetic, with a secondary neon blue accent alongside the primary orange "event horizon" glow. A few minimalist football touches are woven in (the draft board grid mockup) but the site is not fully space-themed or fully football-themed — it's a deliberate blend.
- **Tagline / core concept:** "Where the data reaches its endpoint." The brand metaphor is gravity: scattered stats, trends, and matchups all collapse toward one clear number. The top pricing tier is literally named "Singularity" — the endpoint the whole brand points toward.
- **Voice:** confident, data-first, anti-"gut feel". Founder is a data analyst who got tired of vibes-based rankings.

## Design system
- Colors: `--void` (#07070C, near-black bg), `--void-panel`/`--void-panel-2` (card backgrounds), `--horizon`/`--horizon-gold` (orange/gold accretion-disk accent, primary), `--neon-blue`/`--neon-blue-dim` (secondary accent, deliberately present throughout — ticker, nav, node numerals, footer, not just decorative glows), `--star`/`--star-dim` (text)
- **Light mode exists** alongside the dark theme above (dark is still the default). Activated via `@media (prefers-color-scheme: light)` plus an explicit `:root[data-theme="light"]` override, toggled by the sun/moon button (`app/ThemeToggle.js`) on every page, persisted to `localStorage`. Theme-aware values that aren't plain hex (shadows, the starfield dot color, the ticker/menu-btn scrim, orbit-ring lines) are done as `--x-rgb` custom properties consumed via `rgba(var(--x-rgb), alpha)` — **never bake a theme-specific color into a static SVG data-URI**; that's what broke the feature-list bullet icons in light mode the first time (see globals.css `.feature-list li::before`, now a `radial-gradient` using `var(--void-panel)` instead).
- Fonts: Space Grotesk (headings), Inter (body), IBM Plex Mono (data/stats/mono) — loaded via `next/font/google` in `web/app/layout.js`, referenced in CSS as `var(--font-space-grotesk)` etc.
- Signature motifs: starfield background (mouse-parallaxed), dual radial glows (orange + blue), a draggable orbit ring of "signal chips" in the hero, an orbital hub-and-node selector currently showing 5 of the 6 tools (Best Ball Rankings is sunset — see "Product features" — its node/panel were removed and the arc's `--nx`/`--ny` offsets recomputed for 5 nodes, not 6), a gravity-well playground (canvas particle sim) as the last section before the footer, click-burst micro-interactions on buttons
- No page-break dividers between sections (an earlier "orbit divider" motif was removed by request — don't reintroduce it unless asked)
- **Every page shares one header/ticker setup**, `app/SiteHeader.js` — a full-width fixed `.site-header` bar (plain in-flow `.brandmark` on the left, not a floating pill), nav links spread across a wide center band with an invisible equal-width spacer balancing the brand on the other side, Get Started/Sign In bookending the section links, theme toggle fixed independently at top-right, plus the fixed telemetry ticker above it. Below 1180px width it collapses to the hamburger + `.radial-menu` fallback instead (a full link row doesn't fit at that width). `SiteHeader` fetches its own auth state and real ticker data (latest `redraft_rankings` trend rows) and mounts `InteractiveScript` once, so no page needs its own copy of any of this — it fully replaced the old per-page-type brand marks (tool pages' fixed floating pill, auth/legal pages' static `.auth-back` link, and Player Season Simulations' one-off static/neon-blue pill variant). Nav/radial-menu links point at `/#section` (not bare `#section`) so they work as a real navigation back to the homepage from any other page — `InteractiveScript` only intercepts + smooth-scrolls when already on that path. **Gotcha:** `html{scroll-behavior:smooth}` silently breaks the browser's native scroll-to-fragment-on-load (`scrollIntoView({behavior:'auto'})` inherits that CSS setting instead of jumping instantly); `InteractiveScript` works around it with an explicit `behavior:'instant'` scroll-to-hash on mount — don't "simplify" that away.

## Pricing tiers
Tiers are framed as **titles the subscriber earns**, not plan names:
- **Stargazer** — Free
- **Explorer** — $9/mo (~$7/mo annual), floating "MOST POPULAR" ribbon badge (the in-card eyebrow label itself reads "Standard Access" to avoid duplicating the popularity claim in two different words)
- **Singularity** — $24/mo (~$19/mo annual), marked "Full Access"

Pricing section includes a "14-DAY REFUND · CANCEL ANYTIME" reassurance line beneath the cards. The Pricing section comes right after Tools, before the Feed/newsletter section (order was deliberately swapped from an earlier build where Feed came first).

Naming history (don't reuse): Navigator, Pathfinder, Voyager, Orbiter, Ascendant, Drifter, Rover, Sojourner, Nomad, Wanderer were all considered and rejected before landing on Explorer.

## Current state (as of this build)

**Stack:** Next.js 16 (App Router, JavaScript) + Vercel (hosting target) + Supabase (auth + Postgres) + Stripe (payments). Chosen because it's the most-documented "indie SaaS" combination and sets up the React migration this project always intended.

**Structure:**
- `index.html` — the original static landing page, kept at repo root as a design reference. No longer the live site.
- `web/` — the actual Next.js app. This is what deploys.
  - `app/page.js` — the landing page (Server Component; fetches the 3 most recent rows from the `posts` table for the Feed section)
  - `app/SiteHeader.js` — shared by every page (see Design system for what it owns and replaced); the one thing every `page.js` renders instead of its own header markup
  - `app/InteractiveScript.js` — all client-side interactivity (ticker, scrollspy, draggable ring, gravity playground, pricing tilt, theme toggle click handler, initial hash-scroll on load, etc.) as one client component, mounted once via `SiteHeader`
  - `app/ThemeToggle.js` — the sun/moon button, rendered on every page via `SiteHeader`
  - `app/login/`, `app/account/` — auth pages. `app/account/actions.js` has `openBillingPortal()`, a Server Action that creates a Stripe Customer Portal session for the signed-in user and redirects them to it
  - `app/privacy/`, `app/terms/`, `app/disclaimer/`, `app/contact/` — legal/trust pages, linked from the footer. Share a `.legal-card` prose style in globals.css. The Disclaimer page and the ToS both explicitly state the content isn't intended for gambling/wagering use and disclaim liability for related gains or losses — **don't water that language down**, it was added deliberately for liability protection. Contact page currently shows the founder's personal Gmail as a placeholder support address.
  - `app/api/checkout/route.js` — creates Stripe Checkout Sessions
  - `app/api/webhooks/stripe/route.js` — verifies Stripe signatures, provisions tier in Supabase

  - `proxy.js` — Next.js 16's renamed `middleware.js`; refreshes the Supabase session cookie
  - `supabase/migrations/0001_profiles.sql` — the `profiles` table schema (id, email, tier, stripe_customer_id, stripe_subscription_id) with RLS + auto-create trigger on signup
  - `supabase/migrations/0002_posts.sql` — the `posts` table (title, url, published_at) powering the Feed section's "Recent Drops" cards. Public read via RLS, no client-side write policy — new posts are added by hand through the Supabase Table Editor, not code
  - `app/tools/*/page.js` — **four of the six advertised features are real, tier-gated product pages reading real Supabase data**, not landing-page mock previews (see below). `lib/tier.js` (`getUserTier()`) is the shared helper every one of these pages uses to resolve the signed-in user's tier server-side.
    - `app/tools/redraft-rankings/` — `supabase/migrations/0003_redraft_rankings.sql`. Batched by `season`+`week`; always shows the highest week/season present. Explorer+ (teaser: top 10 for free/signed-out).
    - `app/tools/best-ball-rankings/` and `app/tools/compare-best-ball/` — **sunset "for now"**: both were swapped for a static, zero-Supabase-query "paused" placeholder (no tier check, no data fetch — the point was to cost nothing to serve while paused). The old live implementation (full `best_ball_rankings` query, ceiling-range/hit-probability rendering, CSV export, position search) is still in git history on `main` before this change if it needs to come back; the `0004_best_ball_rankings.sql` table and its later migrations (`0009`–`0016`) are untouched in Supabase. `BestBallSearch.js`/`ExportCsvButton.js`/`TeamBadge.js` components are still in the repo, just unused by these two pages now.
    - `app/tools/draft-board/` — `0005_draft_board.sql`. Grouped by round, `?type=startup|rookie` toggle, `is_stack`/`stack_note` render as a STACK badge. Scoped by `season` (highest present) per `board_type`. Explorer+, but the teaser boundary is "Round 1 only" rather than a row count, via `.lte('round', 1)`.
    - `app/tools/player-simulations/` — `0006_player_simulations.sql` (floor/median/ceiling per player). Renders a CSS range-bar per row, not just numbers. **Singularity-only** — Explorer does NOT get full access here, unlike the three above; this matches the pricing copy exactly and is worth double-checking whenever this page is touched.
    - `app/tools/prospect-rankings/` — `0007_prospect_rankings.sql`, scoped by `draft_class` year, split into Wide Receivers/Quarterbacks sections. **Free for everyone, no tier gating at all** — it's a Stargazer (free-tier) benefit per the pricing copy.
    - All gating happens server-side in the Supabase query itself (`.limit()`/`.lte()` based on tier), not via CSS — a free visitor's page response never contains the extra rows to begin with.
    - New data is published by hand via the Supabase Table Editor (CSV import works for bulk updates) — see each migration file's header comment for the exact column shape.
  - `app/my-team/` — the team importer (step one toward Team Analysis). `actions.js` `lookupSleeperTeams()` pulls every 2025 Sleeper league a username plays in and returns their roster + league format + this-week matchup (opponent, record, and a projected score from our redraft projections over each side's starters); `saveTeam()` upserts a snapshot into `saved_teams`. All of this is client-side aggregation via `web/lib/portfolio.js` `buildPortfolio()` (unit-tested, `web/test/portfolio.test.mjs`).
    - **Team Analysis (the deeper analysis layer) is NOT built yet.** Still missing: the age/contention-window computation. Model-side groundwork is done — `model/player_meta.R` (`player_meta(seasons)` → per-player age/draft/exp/size, keyed on `gsis_id` which == `load_player_stats$player_id`, carries `sleeper_id` for the `/my-team` join) and `model/age_curve_analysis.R` + the README section. No `player_metadata` Supabase table yet — its schema waits on what Team Analysis actually computes.

**Known local-dev quirks (not code bugs):**
- The Stripe CLI and Supabase CLI both needed installing via direct GitHub-release binaries to `~/bin` instead of Homebrew, because this machine's Xcode Command Line Tools are outdated (`brew install` fails; fixing it needs `sudo`/the user's password, which cannot be run from here). Same story for the Vercel CLI, except that one installs cleanly via `npm install -g vercel` since it's pure JS.
- Supabase's built-in email sender has a low rate limit on the free tier, which is why "Confirm email" was temporarily switched off during local testing. **It has since been re-enabled** — new signups now require clicking a confirmation link before they can sign in.
- Supabase validates signup email domains for deliverability — `example.com`/`.test` addresses are rejected; use a real domain (e.g. `mailinator.com` for disposable test inboxes) when testing signup by hand.
- Setting a Vercel project's Root Directory via `vercel project update` isn't exposed in the CLI; had to PATCH `https://api.vercel.com/v9/projects/{id}` directly using the token from `~/Library/Application Support/com.vercel.cli/auth.json`.
- The Browser pane used for visual QA in this environment intermittently suspends rendering on a tab (`document.hidden` goes `true`, screenshots return stale/blank frames, `scrollTo` stops sticking). Workarounds that have worked: `tabs_select` to re-front the tab, `resize_window` to force a repaint, or falling back to reading computed styles via `javascript_tool` instead of a screenshot when a picture isn't strictly necessary.
- When verifying a change against fresh Supabase data (new rows, not just new code) via the local dev server, a plain `rm -rf web/.next/cache` + restart is sometimes NOT enough for the new data to show up — this Next.js fork appears to cache `unstable_cache` results somewhere under `web/.next` beyond just the `cache/` subfolder. If a server-computed value still reflects pre-update data after a cache-only clear and restart, wipe the whole `web/.next` directory (not just `web/.next/cache`) and restart before concluding there's a real code bug. **Order matters**: stop the dev server first, *then* `rm -rf web/.next`, *then* start a fresh server. Deleting `.next` while a server process still has it open corrupts its on-disk state (`ENOENT`/`build-manifest.json`/SST-file errors, ends in a 500) and needs a clean stop → wipe → start cycle to recover, not another cache clear on top.
